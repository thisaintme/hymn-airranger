# Smoosic score editor — proof of concept

A separate native macOS window embeds the real Smoosic editing UI, using a pinned
local build (Smoosic commit 1427042ef0d6b9d8684b140c8f2a489270e8cc9f, package 1.0.44).
This is an evaluation, not a replacement of the production score model.

## Try it

Choose **Score editor (PoC)…** from the main window or File menu. Choose **Test
study**, **Copy current song**, or **Open MusicXML / editor draft…**. PDF conversion
remains in the main app. Opening/copying a score does not change a .hymn project.

Click a note. A–G sets pitch; = and - transpose; comma and period shorten/lengthen.
The labelled toolbar provides common actions, Undo and Hear note. Smoosic's menus
provide its extended notation and tuplet operations. The syllable field can set
verse 1–8 on the selected note. Duration edits can redistribute notes inside a
measure: inspect the result and use Undo. This is Smoosic's editor behaviour, not
an assurance that unselected notes stay fixed during duration operations.

**Save editor copy…** saves a .hymneditor file containing the complete uncompressed
Smoosic JSON plus original input MusicXML and initial comparison findings. Reopen
that file through the editor, not the main project's Open command. It does not
round-trip through our restricted music engine. Do not edit this file as code.

The editor autosaves after changes settle (about one second). Watch the autosave
status, or use Save editor copy before closing. **Recover autosave** reopens the
last draft after restart. Recovery is in Application Support/HymnAIrranger/EditorPoC,
separate from saved hymn projects. A previous recovery file is also kept. These
files contain score/lyric data and stay local. They never contain the app API key.
The PoC does not integrate its undo with the main Versions panel; upstream Undo
is connected, but Redo and named editor revisions are not connected yet.

## Preservation gate

Smoosic JSON is authoritative for the experimental editing copy. MusicXML exports
are experimental. We report differences in event pitches, performed durations,
written values/dots, tuplet ratios, ties and lyrics on initial import/export.
This bounded comparison is NOT a complete audit of all notation or layout.
Missing per-part timing divisions and fractional MusicXML durations from Smoosic
are flagged: the production importer
requires exact integer durations and may reject such exports. We do not round
these values to manufacture a successful test. Do not rely on editor output for
rehearsal without comparing it with the source. There is deliberately no automatic
Apply-to-project or background replacement of the current arrangement.

**Export → Editor diagnostic report…** exports comparison findings/part counts;
review it before sharing. Save your .hymneditor draft for actual editor data. PDF,
MP3 and main-app version integration are not yet connected to the editing copy.
Hear note is a local oscillator, not a downloadable soundfont. Space/P audition a
selected note rather than starting Smoosic's unconfigured sample player.

## Integration and dependencies

Resources are downloaded at build time only and hash-checked against
Scripts/smoosic-dependencies.json. The release JS includes its bundled dependencies.
Smoosic source: https://github.com/Smoosic/Smoosic/tree/1427042ef0d6b9d8684b140c8f2a489270e8cc9f
Smoosic licences: LICENSE and LICENSE.md at that pinned commit, copied into the app.
jQuery 3.7.1 (MIT): https://github.com/jquery/jquery/tree/3.7.1

The adapter constructs Smoosic's UI without the default sample-download startup;
those pinned APIs need reevaluation before upgrading. Three narrow, hash-checked bundled JS adaptations bypass the cosmetic XSLT
pretty-printer, preserve the written type already present on imported tuplet notes
after the upstream note constructor, and propagate conversion errors instead of
substituting an empty default score. The XML exporter itself is not repaired.
Styles omit external font-face loads and use system fonts/text controls. No font
files or sound samples are included. The in-app page blocks outgoing connections,
external navigation, forms and objects; the WebKit data store is nonpersistent.
The native bridge accepts fixed commands, bounded typed messages and explicit file
panels. XML DTD/entity declarations and unsafe JSON constructor fields are rejected.

## Findings from the proof of concept

The original four-part test exercises pitches, ordinary and dotted durations,
triplets, a same-pitch tie, a rest and two lyric verses. Initial investigation found
that Smoosic's importer overwrote imported triplet stem values while constructing
notes. The adapter preserves the explicit input type (no pitch/timing inference).
Native save/reload preserves the tested musical properties; some internal tuplet
IDs and text CSS classes regenerate, so a byte-identical reserialization is not
claimed. The saved native JSON itself is kept verbatim in the editor document.

The pinned XML exporter omits divisions from later parts and emits fractional
numeric durations for triplets. The existing strict Hymn importer rejects the
example's export. This is an explicit remaining integration gate, not a passing
lossless round-trip claim. The diagnostic report makes it visible. No production
transfer, automatic rhythm repair or automatic re-arrangement is added.

## Acceptance evidence

Tests must exercise actual bundled file URLs in WKWebView (not only a browser
demo), real Smoosic edits and undo, native-draft save/reopen, two lyric verses and
tuplets, unchanged main projects, local recovery and visible interchange findings.
Consult the accompanying CI results. This prototype does not establish all-format
MusicXML fidelity or production readiness.
