Hymn AIrranger

A choir-first Mac application for familiar melodies, singable parts, and matching practice material.

This is the setup guide, not the application. The repository contains source code and an original notation example. Generated MP3 demonstrations remain in the original downloadable archive. The shared music core passed 18 tests on Linux. The original delivery did not compile or run the native Mac app with macOS frameworks; check the repository Actions tab for subsequent build results. This is not a finished or notarized installer.

Build on your Mac

01
Use an Apple Silicon Mac, macOS 14 or later, with Apple's Command Line Tools or Xcode. Clone the repository or extract its source archive to a writable folder.
02
Read README.md and inspect Build App.command. Run that command file. It downloads pinned notation/audio resources, tests the core, and attempts the native build.
03
After a successful build, Finder reveals Build/Hymn AIrranger.app. Start with the original study and the Mac acceptance checklist.

Native compilation fixes may still be required. A build failure is recorded in Build/build.log. Do not disable macOS security protections.

Made for this choir

The starting texture is Soprano · Alto · Lower voice, with a separately arranged tenor-present alternative. Generic bass assumptions do not override the singer's configured range.

The melody is checked by ear. AI proposes limited harmony changes; the music engine checks them. Accepted edits retain exact versions. Practice, notation, and exports use the same notes.

Range defaults are provisional. The current engine is deliberately limited to simple tonal drafts, not a finished professional arranging system.

Try the original development study

The original eight-bar study is supplied as a project file, MusicXML, and MEI in Examples. It is not one of your named hymns.

To regenerate WAV practice tracks with the shared Swift synthesizer, run:

swift run -c release hymn-cli demo /tmp/hymn-demo

Generated MP3 demonstrations remain in the original downloadable archive, not in this repository. Those demonstrations used FFmpeg encoding and do not validate the native application’s separate MP3 encoder. See the example notes.

Input boundaries

PDF: experimental cloud extraction with explicit full-file upload consent; always check the notes and words.

Singing: experimental local monophonic transcription, up to 90 seconds. No accompaniment or full-recording separation.

YouTube: save/open a reference link, not extract the video's audio.

What needs validation

Native build and UI, Verovio engraving, actual A4 PDF printing, Keychain and microphone, native MP3 encoding, live AI requests, real import accuracy, and musical suitability for your repertoire.

See the test report, product plan, and architecture notes.

No existing hymn melody, commercial sound set, or font file is included. Check permissions before arranging or distributing protected songs. Local practice is designed to work without a cloud key; cloud generation requires a separately configured API account. No API credentials are supplied or requested in chat.
